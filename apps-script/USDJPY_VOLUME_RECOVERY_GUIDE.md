# 東京市場ドル円スポット出来高 更新復旧ガイド

## 目的

手動更新と共通自動更新を同じ処理へ統一し、日銀の最新公表分を
`USDJPY_Volume` シートと `data/usdjpy-volume.json` に反映します。

## 原因

- 共通スケジューラーが `DocumentLock` を保持したまま、出来高JSON反映処理が
  同じ `DocumentLock` を再取得していました。
- Apps ScriptのLockは再入できないため、30秒後にタイムアウトしていました。
- 出来高だけの個別トリガーと共通トリガーが併存し、競合しやすい状態でした。
- 祝日を単純な平日計算で処理していたため、対象日と公表日の対応を誤る可能性がありました。

## Apps Scriptへ反映する必須ファイル

同名ファイルの中身を、リポジトリ内の最新版へ差し替えます。

1. `MarketReportMenu.gs`
2. `MarketReportMasterScheduler.gs`
3. `UsdJpyVolumePageAutoUpdate.gs`
4. `UsdJpyVolumeJsonFlexibleSync.gs`

ファイル自体を削除する必要はありません。`MarketReportMasterScheduler.gs` が
存在しない場合だけ、新しいスクリプトファイルとして作成します。

## メニュー・関数重複を整理する推奨ファイル

次の2ファイルも最新版へ差し替えると、重複した `onOpen` と市場データ同期関数が
解消されます。

1. `TokyoFlowSync.gs`
2. `VerifiedMarketDataSheetSync.gs`

## 反映後の操作

1. 全ファイルを保存します。
2. スプレッドシートを再読み込みします。
3. `WEB版マーケットレポート` → `東京市場ドル円出来高の状態を確認` を実行します。
4. `東京市場ドル円出来高を今すぐ更新` を実行します。
5. `共通自動更新を設定・修復` を1回実行します。

`共通自動更新を設定・修復` は、古い出来高個別トリガーを削除して共通トリガーを
8本に整理します。

## 自動更新時刻

- レポート共通更新: 07:30 / 12:30 / 16:30 / 21:30
- 再確認: 08:30 / 13:30 / 17:30 / 22:30
- 東京市場ドル円スポット出来高: 21:30、失敗時は22:30に再確認

日銀の出来高は日次公表なので、1日4回のPDF OCRは行いません。

## 状態確認で表示する内容

- 日銀公式一覧の最新公表日
- `USDJPY_Volume` シートの最新公表日
- 公開WEB JSONの最新公表日
- 共通トリガー数と古い個別トリガー数
- 前回更新の成功・失敗と実行時刻

3つの公表日が一致した場合だけ「最新です」と表示します。
