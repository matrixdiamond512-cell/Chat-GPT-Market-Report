## 3. デザイン実装

1. 元画像を**参照画像**として使い、背景・ヘッダー・パネル矩形・余白・罫線・見出し帯・アイコンの位置を計測して、編集可能なレイアウト定義（JSON/SVG/HTML+CSS/Pillowの座標定義など）に分離する。
2. **完成PNGを文字の上から塗りつぶして再利用する方法は禁止**。出力時に16パネルのテキスト・数値・表をすべて描画する。ヘッダー背景など文字のない装飾領域の再利用は可能。
3. フォントサイズ・折返し・行高・余白・表セル高さを動的計算する。日本語文字のはみ出し、表の行衝突、アイコンとの重なりを検出し、閾値内に収まらないときはDRAFT/BLOCKED。
4. 16個の番号・パネルの見出し・位置は固定し、パネル間ギャップと色調が正本に概ね一致することをスクリーンショットで人手比較する。pixel-perfect自動一致を文字内容の差まで求めず、構造上の類似性を検査する。
5. 入力が完全でも可読性が悪ければ正式出力不可。プレビューはDRAFTと明確に区別する。

## 4. 単一データ契約と来歴

- `report_id=YYYY-MM-DD_HH-MM`、`revision`、`snapshot_id`、`bodyHash`（または既存契約の対応フィールド）、`title`、`date`、`time`、`fullText`を照合する。既存レポートがそれらを欠く場合**後付けで架空ID・架空スナップショットを作らない**。追加データの作成手順と不足理由を監査へ記録する。
- 数値レジストリの1件には最低：`fact_id`、`instrument`、`display_value`、`raw_value`、`unit`、`price_basis`（現物/先物、終値/清算値/遅延参照値、取引所・限月）、`as_of`、`comparison_basis`、`change_value`、`change_pct`、`direction`、`source_name`、`source_url`、`source_timestamp`、`body_excerpt`、`verification_status`を持つ。出典が取得不能なら理由を明示。
- 別商品のスポット金とCOMEX先物、WTI日足終値と清算値、CMEと大阪先物、USD/BTCとBTC/USDを**同一系列として混用禁止**。
- 出力数値はレジストリから参照し、表セル単位にfact_idを紐付ける。表示文字の数値・符号・前日比・方向は自動計算/照合する。
- レジストリにない値は描かない。本文にない数値を描画時に新規取得して足さない。市場の一次情報照合は**本文・原本の確定工程**で行い、本文変更時はbodyHash/revisionを更新して再検証する。
- 毎回の本文がそもそも古い/誤った相場データなら、PNGだけ直して正式公開してはいけない。原本修正と根拠の差分管理を行う。

## 5. イベントと時系列

- イベントごとに `event_id/title/date/timeJST/precision/sourceURL/confirmedAt/importance/affectedMarkets` を持つ。米国の発表時刻は当該日付の夏時間/冬時間を使い日本時間へ変換。
- 2026-10-13版の対象：米大手銀行決算、米CPI、米PPI、米小売売上高。v20ブランチに登録された時刻は一次情報再照合待ちとして扱う。**確認できない発表時刻は時刻未確定**。
- 過去のニュースの時系列は「開始前→開場→中盤→終盤→引き継ぎ」の順序と根拠を必須にする。記事時刻と市場反応時刻を混同せず、根拠がなければ具体的な時刻を出さない。
- 元画像の05の `25:00/27:00/29:00` 等は根拠がない限り再利用禁止。重要イベント表には予定と実績を混在させない。
